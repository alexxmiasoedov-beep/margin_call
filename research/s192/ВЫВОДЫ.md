19.11.2026. Сбор данных для проверки находок, найденных после расчёта, и пограничных кандидатов на выборке до трёх
прежних периодов (10.2020–09.2022, 10.2022–09.2024, 10.2024–10.2026). Доходы, сделки и плацебо **не считались** —
только данные, их проверка и частоты событий.

## Главное

- **Собран период 10.2019–09.2020 (с прогревом с 08.09.2019) в форматах прежних периодов:** 15-мин свечи и фандинг
  59 перпов, часовой спот Binance (58 монет), часовые свечи к воне Upbit и Bithumb (25 монет), дневная панель
  и недельные признаки s183.
- **Перпов в этом периоде мало.** В 2019 г. торговались только BTC (с 08.09), ETH (с 27.11) и BCH (с 12.2019).
  Альты пошли с 01.2020: 11 перпов в 01.2020, 24–25 в 02–05.2020, 59 к концу 09.2020.
- **Для альтов период фактически 8 месяцев (02–09.2020).** Ликвидных альтов на срез — медиана 17, во второй
  половине — 20. В прежних периодах — 120 / 180 / 270.
- **Частоты событий находок ниже прежних:** у s152 — в 2–3,5 раза, у остальных — в 5–30 раз. Двойник 👀 «доля Кореи
  ≥ 20%» на этом периоде проверить нельзя: ноль событий. Остальные находки — от 77 событий за период (s180) до тысяч
  (трейлинг ATR, s152).

**Подробности сбора.**
- **Архив USDT-M начинается с 01.2020.** Месяцы 09–12.2019 у BTC, ETH, BCH взяты с публичного адреса
  `www.binance.com/fapi/v1/klines` и `…/fundingRate`, без ключа (`fapi.binance.com` из облака закрыт, 451). Получено
  10 969, 3329 и 1213 свечей, 338, 104 и 37 начислений.
  - На пересечении (01.01.2020, BTC и ETH) ответы API и архива совпали по всем колонкам.
  - Ответы API — в кэше `api_cache/`.
- **Список перпов — весь листинг архива, как в s117.** Снятые позже перпы (LEND, BZRX и др.) в нём есть.
  - ENJ, FLM, HNT запущены 28–29.09.2020: меньше 3 суток свечей, отброшены правилом s117.
  - Стык с `k_2020.pkl`: из 62 перпов, торговавшихся 01.10.2020, нет только этих трёх. У BTC, ETH, LINK закрытие
    30.09 23:45 равно открытию 01.10 00:00 в `k_2020.pkl`.
- **Агрессивные покупки (`tb`) есть почти везде.** Нули — 48 свечей в первые дни BTC (09.2019), дальше до 44 свечей
  в месяц (< 0,1%).
- **Фандинг полный.** Единственный пропуск архива — QTUM 02.2020 — дозаполнен с API (31 начисление).
- **Корея.**
  - Цены всех рядов сверены с перпами: цена в вонах / (цена перпа × курс) = 0,998–1,007. Курс — KRW-BTC Upbit / BTC перп,
    медиана 1187,5 вон за $.
  - **EOS** взят под нынешним кодом рынка KRW-A (переименование в Vaulta, история с 2019 г. сохранилась, цена сверена).

    (LTC, DASH, XMR, ZEC, OMG, ICX, ZIL, SXP и др.; DEFI — индекс). Часть из них торговалась к воне в 2019–2020 гг.
  - Другие переименования (FTM → S, MKR → SKY, LEND → AAVE) истории периода не дают.

## Ограничения

- **Редкость перпов.**
  - До 02.2020 альтов нет. Признакам с прогревом 30 сут (возраст s183, вселенная s152) события доступны
    с 02–03.2020.
  - 30-суточный максимум s180 считается и по заглушкам до запуска, как в прежних периодах.
  - На вторую половину (04–09.2020) приходится 60–90% событий.
- **Выживаемость.**
  - Перпы — полный список.
  - Корея — только рынки, живые сегодня (плюс EOS через KRW-A). Доля Кореи у монет со снятыми рынками неизвестна,
    у таких монет `krv` пустой.
- **Чего нет.**
  - OI и позиций счетов: архив `metrics` — с 12.2021, `feat_oi.py` дал пустые колонки.
  - Снимков CMC топ-200 до 07.2020: `mcap` есть у 55% строк, с 06.07.2020.
- **Режим рынка.** В 03.2020 — обвал (12–13.03). На этот месяц приходится заметная часть событий s190 и пампов.
- **Прогрев в файле свечей.** `k_2019.pkl` начинается 08.09.2019, в сентябре 2019 г. торгуется только BTC. Скрипты,
  которые не режут события по началу периода (например, `s190/g2.py run`), могут взять этот месяц — фильтровать
  t ≥ 01.10.2019.
- **BTC нет в панели s183 и во вселенной s180 — во всех периодах.** В `s12/perp_kind.pkl` «BTC» попал в список
  tradfi. Так и в прежних периодах, оставлено для совместимости.
- **Середина периода** `MC_CUT=2020-04-01` — календарная. По событиям половины неравны.

## Как запускать наши скрипты на новом периоде

**Переменные:**
- `MC_K=/home/user/mc_data/s192/k_2019.pkl`;
- `MC_F=/home/user/mc_data/s192/fund_2019.pkl`;
- `MC_CUT=2020-04-01`;
- для `s118/kr_build_oos.py` — `MC_KC=/home/user/mc_data/s192/kc`.

**Папка запуска:**
- `/home/user/mc_data` — для скриптов на `s15/common` и `s43/oi_test` (нужен `s22/grid.pkl`);
- `/home/user/mc_data/s192/work` — для скриптов, которые читают `s2/`, `s15/kr_panel.pkl`, `s23/spotcache` из текущей
  папки (аналог `~/mc_2020`).

**Период «2019–2020» в чужих PER — `period.py`** (файлы других исследований не меняются):
- запись строится из записи «2020–2022» заменой дат (01.10.2020 → 01.10.2019, 01.10.2022 → 01.10.2020,
  середина → 01.04.2020) и путей (`s117/k_2020` → `s192/k_2019`, `s88/oos2020` → `s192`, `~/mc_2020` → `s192/work`);
- добавляется первой строкой в PER, PERIODS и PERS загруженных модулей, в том числе `common182` и `common183`,
  которые скрипты импортируют внутри функций.

```
cd /home/user/mc_data
export MC_K=/home/user/mc_data/s192/k_2019.pkl MC_F=/home/user/mc_data/s192/fund_2019.pkl MC_CUT=2020-04-01
python3 <repo>/research/s192/period.py show research/s185/oos.py            # какую запись получит скрипт
python3 <repo>/research/s192/period.py run research/s185/oos.py run 2019–2020
python3 <repo>/research/s192/period.py run research/s180/round_test.py run 2019–2020
python3 <repo>/research/s192/period.py run research/s190/g2.py run 2019–2020   # события с 01.10.2019
cd /home/user/mc_data/s192/work && python3 <repo>/research/s192/period.py run research/s152/drop_test.py run 2019–2020
```

- Функции `report()` после регистрации включают «2019–2020» первой строкой — нужен итог `run` нового периода.
- **s187/bt.py** читает сигналы из `/home/user/mc_data/s187/signals_<период>_<1h|4h>.pkl`. Для нового периода готовы
  только часовые сигналы пяти индикаторов ATR (`s192/signals_2019–2020_1h.pkl`) и бары (`s192/bars_2019–2020.pkl`).
  Нужна ссылка в папку s187 под новым именем и сигналы 4h (или запуск только 1h).
- **Скрипты с `MC_Y0`** (`s117/load_oos.py`, `s88/oos_fetch.py`, `s88/oos_test.py`, `s118/spot_oos.py`) рассчитаны
  на двухлетние периоды и архив USDT-M, который начинается с 01.2020. Для этого периода их данные заменяют файлы s192.
- **Пересборка:** `load_2019.py` → `spot_2019.py` → `kr_2019.py` → `period.py s183` → `freq.py`. Кэши
  (`cache/`, `spotcache/`, `api_cache/`, `kc/`) делают повторный запуск без сети.
- **Рабочая папка `work/`:** ссылки на данные, затем из неё `MC_K=… MC_KC=/home/user/mc_data/s192/kc python3
  <repo>/research/s118/kr_build_oos.py` и `MC_K=… MC_F=… python3 <repo>/research/s15/kr_panel.py`.
